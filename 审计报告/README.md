## 为什么要合并

对同一仓库出现过**三份相互独立**的审计报告（代号 A / B / C），它们的结论有重叠、有互补、也有**正面冲突**。
为判定冲突，又做了**两轮独立裁决**——由未参与任何原报告的 agent 亲自读代码、实跑脚本与模拟引擎来判定。
本目录的权威清单就是这三份 + 两轮裁决的合并结果。

> ⚠️ **两轮裁决推翻了若干净翻原始报告会踩到的结论**，例如：
> - C 报告列为「最高优先级、建议立即修」的 **CI 编码问题，经实证判定不成立**（现代 pip ≥25.0 先试 UTF-8，locale 只是兜底；CI 那次运行 19 个 job 全绿）
> - B 报告与 C 报告都把 `stem-optimize` 子项目的许可证状态判为「完善 / 相互印证」，**实为该目录声明「不得作为开源再分发」与根 MIT 正面冲突**
> - A 报告曾把 010-STEM模拟 的 `np.trapezoid` 兼容性问题列为「被推翻」，**经裁决该条其实成立**

## 权威清单里的字段怎么读

- **提到过的报告**：`A` / `B` / `C` 的组合。`三方共识` 表示三份报告各自独立发现；`仅X提出` 表示只有一份发现。
- **验证状态**：`经独立对抗验证` 最强（有独立 agent 尝试推翻但未成功）；`单方复核` 次之；`未验证` 表示只有单个 agent 的结论，请当线索而非结论。
- **结论**：成立 / 部分成立 / 已被推翻 / 存疑待验。
- **更正**：裁决或合并过程中对某份报告原始说法的修正。
