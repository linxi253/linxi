# v4.4 修复说明

本版本按三轮代码审查（内部两轮 + 外部证据化审查 `review/2026-09-28/`）集中
修复科研数据正确性与可靠性问题。多数修复附带可复现的回归测试
（`tests/test_regression.py`）。

## 科研数据正确性（P1）

- **旋转元数据不再导致静默转置**（外部 R1，实测复现）：解码统一加
  `-noautorotate`，输出保持编码方向的像素矩阵，与 probe 宽高严格一致；
  检测到非零旋转角时告警并记入清单。90°/270° 旋转不改变总字节数，
  此前"帧完整性检查 + TIFF 维度校验"全部通过但像素整体错位。
- **严格解码为默认**（外部 R3）：解码命令加 `-xerror`，FFmpeg 对解码错误
  默认容忍并跳帧且退出码仍为 0，"缺帧"会被静默标记为成功；现在显式失败。
  抢救性提取可用 CLI `--lenient-decode` 或 GUI 勾选"宽松解码"，
  结果带缺帧风险告警。
- **时间轴以实测为准**（外部 R2）："全部帧"模式不再依赖
  avg/r_frame_rate 启发式——count pass 通过 showinfo 捕获逐帧 PTS，
  CSV 写入真实 `source_pts_s`；帧间隔实测不均匀（真可变帧率）时不写
  固定 `finterval`，不给 ImageJ 一个不存在的等间隔时间轴；流级帧率
  检测漏检时由实测 PTS 补发告警。
- **延迟起始流不再复制填充帧**（外部 R7，实测复现）：fps 滤镜的
  start_time 锚定在选中流首帧 PTS（按 ffmpeg 滤镜时间轴换算，扣除
  format.start_time），并显式 `-fps_mode passthrough` 消除 rawvideo
  输出端 CFR 同步在首帧前补帧的第二机制；CSV 记录 `stream_start_time_s`。
- **动态分辨率防转置**：解码链尾部固定 `scale=W:H`，编码流中途改变
  分辨率时强制回到探测规格，而不是按旧宽高静默转置。
- **输入身份绑定**（外部 R6）：哈希、帧统计、解码各阶段之间以
  （大小 + 纳秒级 mtime）指纹校验输入未被替换/追加，失败即中止，
  保证溯源哈希与输出内容一致。

## 可靠性（P2）

- **孤儿隔离区脱离自动清理**（外部 R5）：缺 CSV 的孤儿输出移入
  `.orphans/` 持久目录（不再放会被 24h 清理的 `.partial`），数据永不
  被自动删除；"缺 CSV"不再被当作可自动销毁上次结果的证据。
- **提交前复查输出冲突**：双文件提交区前再次检查目标是否已被其他任务
  创建，把覆盖竞态窗口从小时级压到毫秒级（彻底消除需跨进程锁，未实现）。
- **提交前最后一道取消检查**（外部 R10）：校验/写清单阶段收到取消不再
  发布输出；CSV 写入循环每 8192 行检查一次取消。
- **abort() 二次异常防护**（外部 R11）：清理路径自身的失败（如磁盘满导致
  flush 再抛）不再掩盖原始错误、不再逃出单视频隔离边界终止整批；
  writer 的 abort flush 改为尽力而为。
- **输入校验补全**（外部 R14）：全部帧模式拒绝 `--value`；间隔 1e-320
  这类倒数溢出为 inf 的值被拒绝；目标帧率设合理上限；探测分辨率非正值
  拒绝；JSON 清单 `allow_nan=False`。
- **GUI 配置健壮性**（外部 R13）：配置文件为 `[]`/`null`/数字时不再
  启动即崩（AttributeError），坏配置备份后回退默认值；字段类型逐一校验。
- **解码停滞看门狗 + stderr 有界缓冲**（外部 R15）：120 秒无任何帧输出
  自动终止并报错；stderr 只保留尾部 64 KiB，损坏输入的海量日志不再
  无限累积。
- **junction/symlink 逃逸容错**：输入目录含指向外部的链接时输出路径
  退化为安全目录名，不再让整批扫描崩溃。
- **磁盘保留量上限**：保留量 = min(max(2 GiB, 5%), 32 GiB)，大容量阵列
  （空闲 8 TiB）不再因 400 GiB 的"5%"误拦合法任务。

## 溯源、界面与构建

- 任务级 JSON 清单补充 `input_sha256`、`warnings`（逐视频告警持久化，
  与 README 溯源承诺对齐，外部 R9）、`frame_manifest_path`、
  `timeline_source`；schema_version 升至 4。
- 9–14 位源按 16 位输出时告警"数值线性重映射到满量程"（外部 R8）。
- GUI：高 DPI 感知；计数阶段进度条按估计帧数映射（不再看似卡住）；
  成功日志带输出/清单绝对路径；批结束提示清单目录；新增"宽松解码"开关。
- CLI：取消退出码 130（与失败 1 区分）；`--lenient-decode`。
- `scripts/build.ps1`：按 PROVENANCE.md 逐文件校验 FFmpeg 运行时 SHA-256，
  被替换的 DLL 无法再静默进入发布包；强制使用项目本地 `.venv` 构建。
- `pyproject.toml`：描述从 OME-TIFF 更正为 ImageJ TIFF；版本改为从
  `__init__.__version__` 动态读取（单点化）。
- README 更正"ImageJ 自动虚拟栈"表述（外部 R12：官方 1.53c 实测
  `virtual=false`），并全面更新数据保真约束说明。

## 性能

- count pass 改为轻量链（showinfo + fps，省去全部色彩换射），
  计数遍耗时显著下降；帧数一致性由"除 fps 外滤镜均帧保持"的不变量测试
  保护（`test_decode_filters_are_frame_preserving`）。
- 解码逐帧去掉冗余 `.copy()`（赋值进 memmap 时本身会拷贝）。
