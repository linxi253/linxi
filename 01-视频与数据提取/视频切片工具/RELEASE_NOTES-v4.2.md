# v4.2 修复说明与验收记录

本版本来自一次覆盖逻辑、科学性、可维护性、安全、性能、输入校验、前端与
输出全面性的深度代码审查。v4.1.x 的主流程没有数据损坏缺陷；修复集中在
科学数据保真的三个边角缺口、CLI 自动化接口、断电持久化窗口和若干
校验盲区。版本号从 4.1.1 升到 4.2，因为其中三项修复会改变输出行为。

## 科学性修复

1. **YUV→RGB 彩色转换现在显式声明色彩矩阵/范围。** 旧行为在灰度路径
   按 `color_space`/`color_range` 选择矩阵，RGB 路径却依赖 swscale 按
   分辨率启发式选矩阵——BT.709 高清源会被按 BT.601 换算，产生系统性
   色度偏差。现在 YUV 源转彩色输出时会构建
   `scale=in_color_matrix=..:in_range=..` 滤镜，与灰度路径同一机制；
   源为 RGB 或元数据缺失时保持原有回退行为。**注意：YUV 源的彩色输出
   像素值会因此变化（更正确的色彩解释）。**
2. **位深元数据缺失时按像素格式推断并告警。** 旧代码在
   `bits_per_raw_sample`/`bits_per_sample` 缺失或为 0 时一律按 8 位处理，
   VP9 profile 2 等 10 位源会被静默降为 8 位输出。现在按像素格式名称
   推断有效组件位深（`yuv420p10le`→10、`p010le`→10、`gray16le`→16 等），
   并在结果与清单中记录 `bits_source`；推断发生且位深大于 8 时输出告警。
   同时把 `rgb24` 报告的 `bits_per_sample=24`（打包总位深，非组件位深）
   识别为不可信值回退推断，修正了 8 位 RGB 源被误判为高位深的隐患。
   **注意：部分 10 位文件的输出会从 8 位变为 16 位，体积相应增大。**
3. **可变帧率视频按目标帧率采样时告警。** 帧率上采样检查只比较平均
   帧率；VFR 源在目标帧率≈平均帧率时，`fps` 滤镜仍会在源帧间隔大于
   目标间隔的空档复制前帧——这正是上采样检查自己拒绝的行为。现在
   非"全部帧"模式遇到 VFR 源会输出告警；输出时间轴本身仍是精确的
   采样间隔。

## 输入校验

4. **拒绝 NaN/Infinity 采样值。** `Sampling.validate` 原来只检查
   `value <= 0`，而 NaN 的所有比较均为 False、inf 也通过校验，错误会
   延迟到 `round(nan)` 或 `fps=fps=nan` 处以晦涩形式暴露。现在
   UI 与 CLI 的采样值必须是有限正数。

## 持久化完整性

5. **提交前 fsync。** `memmap.flush()` 只保证数据进入 OS 页缓存，断电时
   未落盘的内容可能丢失或损坏，且输出与清单两文件齐备时孤儿检测无法
   发现。现在 OME-TIFF 堆栈与逐帧 CSV 清单在 `os.replace` 提交前强制
   `fsync`，提交后对目录项 `fsync`（Unix），与既有 JSON 清单的持久化
   机制对齐。

## 接口与易用性

6. **CLI 事件流移至 stderr（破坏性变更）。** 旧行为把进度事件 JSON 行和
   最终结果 JSON 数组混在同一 stdout，自动化调用方无法直接解析。现在
   stdout 只输出最终结果数组，进度/告警事件走 stderr，并且逐帧事件
   改为按 0.1 秒间隔节流（末帧必发），高帧率视频下控制台不再是吞吐
   瓶颈。依赖旧混流输出的脚本需要改从 stderr 读取事件。
7. **GUI 批级进度与速度口径。** 多视频批次下进度条改为按整批加权
   （此前每个新视频会把进度条拉回起点），速度/剩余时间按当前视频起点
   计时（此前按整批耗时摊薄，数值失真），速度栏显示 `[i/N]` 批次位置。
8. **结果记录实际输出大小。** `VideoResult` 新增 `output_bytes`，随
   job manifest 与 CLI 结果输出，GUI 日志在完成行显示 GiB 体积。
9. **`--version`。** CLI 与 GUI 均支持 `--version`。

## 可维护性

10. **版本号单点化。** 此前 `4.1.1` 散布在 pyproject、PyInstaller spec、
    build.ps1、UI 标题、CLI 描述与 job manifest 共 7 处。现在唯一来源是
    `video_extractor/__init__.py` 的 `__version__`，spec 与 build.ps1
    自动读取，升版不再可能漏改。
11. **删除死代码与重复实现**：逐帧清单的多文件分支（v3 序列输出遗留，
    签名同步简化为单文件）、`FrameDecoder` 中与 `ffmpeg.py` 完全重复的
    `_stop_process`。

## 兼容性

- CSV 清单字段不变；JSON 结果新增 `bits_source`、`output_bytes` 两个
  可选字段，旧解析不受影响。
- CLI stdout/stderr 分流为破坏性变更，见第 6 条。
- manifest `schema_version` 保持 2，`tool_version` 变为 `4.2`。

- 全量测试 63 项通过（v4.1.1 为 49 项；新增 NaN/Inf 校验、CLI 流分流、
  位深推断、RGB 矩阵滤镜链、VFR 告警、fsync、输出大小断言，删除 1 项
  死代码测试）。

  Python 与 FFmpeg 运行时可加载）。
