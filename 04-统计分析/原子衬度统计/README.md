# TIF 图像衬度分析工具 v2.5.0

对 TEM/STEM TIFF 单图或多页堆栈绘制多个矩形 ROI，并计算每个 ROI 的逐帧衬度曲线。

## Python 版本与系统要求

- Python 3.10 / 3.11（`requirements.txt` 中 `numpy==2.2.6` 需要 Python 3.10+；若使用更低版本 Python，请改用 numpy >= 1.22 的兼容版本——分位数向量化需要 tuple axis 支持）。
- 需要 Tk 支持：Windows 官方 Python 自带；Linux 请安装 `python3-tk`；macOS 使用 python.org 安装包自带。
- 图形界面依赖 `ttkbootstrap`（其导入期即需要 `Pillow`），首次运行前请完整安装 `requirements.txt`。
- 图内中文标题/轴标签会在启动时自动挑选系统已安装的中文字体（微软雅黑 / SimHei / Noto Sans CJK 等）；若都不可用，程序会在信息面板给出显式告警（历史版本固定写死 `Arial, SimHei`，会导致图内中文渲染为方框）。

## 支持的衬度定义

- 标准差 / 平均强度；
- Michelson 衬度：`(Imax - Imin) / (Imax + Imin)`——**使用全局极值，对单个热像素或宇宙射线事件极端敏感**，含离群点的 ROI 结果会趋近 1；
- 方差 / 平均强度；
- 稳健 Michelson 衬度：`(P99 - P1) / (P99 + P1)`（1%/99% 分位）——抑制单像素离群，与极值版对比可判断离群值影响。**注意：分位数离群抑制只在 ROI 像素数 ≥100 时有效**——3×3=9 像素时 p99 仍含约 92% 权重的最大值，结果与极值版几乎相同（n=9 实测 0.998 vs 0.998）；小 ROI 使用该算法时程序会给出警告。

三种基础定义的数值尺度不同，报告中必须记录所选算法。σ 类统计均为**总体标准差（ddof=0）**，与样本标准差（ddof=1）数值不同，CSV 头部已注明。

**定义域**：四种定义均假定强度非负（`I ≥ 0`）。若 ROI 中出现负强度像素（例如数据已做背景扣除或归一化），Michelson 类会给出 > 1 或负衬度，`std/mean` 也可能为负——这在数学上无意义，程序会在信息面板给出显式警告。ROI 内含 NaN/Inf 像素时，该帧衬度按 NaN 记录。

## 使用流程

1. 打开 `.tif/.tiff` 文件（文件头在主线程解析，像素读取与显示范围估计在后台线程，界面不会假死；压缩文件体积过大时会在加载前询问确认）。
2. 浏览帧并在图像上绘制一个或多个矩形 ROI（放大/平移视图在切帧时会保留）。
3. 选择衬度算法并开始分析。
4. 检查各 ROI 曲线和统计信息（可用"📋 复制"按钮把信息面板内容复制到剪贴板）。
5. 导出 CSV；每列为一个 ROI，每行为一帧。

**显示范围**：默认"锁定灰度范围(全堆栈)"使用全堆栈统一灰度拉伸，避免逐帧自动对比度掩盖帧间强度演化；取消勾选可回到逐帧自动拉伸（均匀帧会自动展开半级，避免退化）。

**ROI 复用**：文件菜单可导出/导入 ROI 坐标（JSON）。导入会替换当前 ROI，越界坐标自动 clamp，尺寸 <3px 的记录被跳过并在日志中说明——同一采集条件下重测时无需重复手绘。

**多帧解析（🧩）**：部分软件（包括 tifffile 在写入 3/4 帧数据时的默认行为）会把多帧堆叠写成 planar RGB/RGBA 单页（`Photometric=RGB` + `PlanarConfig=SEPARATE`），按颜色解析会得到 **1 帧**（前 3 个平面按 RGB 权重混合、第 4 个平面被忽略）。默认按文件声明的颜色语义解析并在日志中说明；若那 3/4 个平面实为帧，勾选"多帧解析"后重新加载即可按帧读取。用 tifffile 写数据时建议显式指定 `photometric='minisblack'`。切换该开关只重新解释当前文件（像素与图像尺寸不变），**已绘制的 ROI 会保留**（越界自动裁剪）；重载失败时复选框回滚到当前数据实际使用的取值。

**ROI 像素口径**：取整规则为下界 `floor`、上界 `ceil`（覆盖所有被拖拽矩形触及的像素），`xmax/ymax` 为开区间端点，对应 `img[ymin:ymax, xmin:xmax]`，实际像素数为 `(xmax-xmin)×(ymax-ymin)`。

## CSV 导出格式

- 文件头为 `#` 注释块：软件版本、导出时间（**含时区偏移**）、源文件路径、算法（显示名 + key）、帧数、图像尺寸、像素类型、TIFF 布局（axes/页数/photometric/planar/通道数/压缩）、采集软件与采集时间（若标签存在）、TIFF 分辨率标签、启发式解析的像素尺寸、ImageDescription、源文件大小与修改时间、各 ROI 的像素坐标与尺寸（像素尺寸解析成功时附**物理面积估算**）、取整规则、σ 口径（ddof=0）、列说明。
- 数据区第一列为帧号 `Frame`（**从 1 开始**，与界面显示及图形 x 轴一致）；若 TIFF 每页带 DateTime 标签且页数与帧数一致，第二列为 `DateTime`（标签原文，便于时间序列分析使用真实采集时刻）；其后每列一个 ROI 的衬度值，再后是每个 ROI 的逐帧**原始强度统计**：`ROI_i_mean`、`ROI_i_sigma`、`ROI_i_min`、`ROI_i_max`——用于区分"结构变化"与"束流/厚度变化"，也便于发现热像素与饱和。
- 文件尾部为 `#` 注释块：每个 ROI 的跨帧统计（有效帧数、均值、σ、范围），与界面统计摘要一致。
- `NaN` 表示"无有效衬度"（例如平均强度或 `Imax + Imin` 为零），不应解释为 0。
- 读取示例：`pandas.read_csv(path, comment='#', index_col='Frame')`（首尾注释块都会被跳过；若存在 DateTime 列，其值为标签原文字符串）。
- 编码为 UTF-8 带 BOM，Excel 可直接打开。
- 像素尺寸来自 ImageDescription 的**启发式解析**，物理面积估算基于该值（已标注"请核对"），且同时写入原始描述串供核对；不同厂商（Gatan/FEI/JEOL）格式差异大，请以原始元数据为准。

## 数据维度支持

入口统一调用 `contrast_core.normalize_tiff_array` 进行规范化：

| 输入形状 | 含义 | 处理 |
| --- | --- | --- |
| `(H, W)` | 单张灰度 | 视为 `(1, H, W)` |
| `(H, W, 3/4)` | 单张彩色 | 自动转灰度后视为 `(1, H, W)` |
| `(C/S, H, W)` | planar 彩色单页 | 转置后转灰度，视为 `(1, H, W)`（勾选"多帧解析"则按帧读取） |
| `(T, H, W)` | 灰度堆叠 | 原样使用（含 `W=3/4` 的窄条堆叠） |
| `(T, H, W, 3/4)` / `(T, 3/4, H, W)` | 彩色堆叠 | 逐帧转灰度后按 `(T, H, W)` 处理 |
| `(T, Z, Y, X)` | 三维层析 | 拒绝，并提示先导出为 `(T, Y, X)` |

无法识别的 4D/高维结构会在加载时给出含 `axes`、形状与建议的明确错误提示。

多帧数据优先使用 `tifffile.memmap` 流式访问；LZW/Deflate 等压缩 TIFF 无法建立内存映射时会自动回退为整卷读入内存（其余 memmap 失败形态，如网络盘/非常规布局，同样回退），超大压缩文件会在加载前提示预计占用并请求确认。加载阶段进度条转为流动模式（不残留旧读数）；若文件 axes 含 Z 轴，日志会提示"Z 切片按帧处理"，避免把层析/系列切片误当时间序列。分析在后台线程中运行并支持取消（收尾瞬间取消也能正确响应，不会出现"提示取消却照常完成"）；**分块按像素预算**（每块约 400 万像素，等价于 float64 约 32 MB，同时不超过 256 帧），因此大 ROI 不再出现"固定 256 帧分块导致内存随 ROI 面积线性膨胀"的问题。单帧输入会计算各 ROI 衬度值（可正常导出）并显示 ROI 强度直方图（含与多帧路径一致的负强度/非有限/小 ROI 警告）。分析进行期间 ROI 编辑、导出与清空被禁止，算法下拉框禁用，完成后的曲线和统计摘要使用分析启动时保存的算法快照；分析完成后切换算法不会使结果失效（导出仍用快照），但会给出"请重新分析"的提示。超长序列（>20000 帧）的曲线会自动抽稀显示（标题中标注抽稀倍数），CSV 始终为完整数据。

加载失败时**不会破坏当前已加载的文件与结果**：状态在后台线程返回之前保持不变，仅在成功后一次性切换。

## 主要文件

- `tif图像衬度分析工具.py`：完整 GUI、ROI、衬度计算与 CSV 导出（CSV 写入使用标准库 `csv`，运行时不依赖 pandas）。
- `contrast_core.py`：无 GUI 依赖的算法、维度规范化、TIFF 头部探测与元数据整理模块（含 `__version__` 版本单源）。
- `tests/test_core.py`：算法、逐帧统计、校验顺序、ROI 取整、维度规范化（含 planar 多帧解析）、TIFF 探测与像素尺寸启发式的单元测试。
- `smoke_test_gui.py`：GUI 冒烟/回归脚本（含加载失败回滚、多帧解析、取消、CSV 结构等用例）。
- `requirements.txt`：运行与测试依赖（版本锁定）。
- `衬度分析v2.spec`：PyInstaller 配置（排除非 TkAgg 后端与 pandas 以控制体积）。
- `dist/`：打包产物目录，未随仓库分发，需用上述 spec 自行构建。

## 注意事项

- 同一 ROI 会应用到所有帧。样品存在漂移时，应先做漂移矫正。
- **极值版 Michelson 对单像素离群（热像素/宇宙射线）极其敏感**；含离群数据请改用稳健 Michelson，或两者对比以判断离群影响。**稳健版的离群抑制要求 ROI ≥100 像素**，小 ROI 下两版结果几乎相同。
- 四种衬度定义的数值尺度不同，报告中必须记录所选算法（CSV 头部已自动记录）；σ 为总体标准差（ddof=0）。
- 平均强度或 `Imax + Imin` 为零时会得到 `NaN`，不应把它解释为零衬度。
- 彩色图像转灰度使用 `0.2989 R + 0.5870 G + 0.1140 B`（四舍五入，RGBA 的 alpha 被忽略）；若原始图像是伪彩色（如 SEM 假色），请先确认灰度物理含义。
- "锁定灰度范围"的灰度范围按跨步采样估计（上限约 200 万采样点），仅影响显示，不参与衬度计算。
- 无压缩 TIFF 在加载期间保持内存映射，会持续占用文件句柄（Windows 下该文件在程序中打开期间无法被移动/删除）。
- 3D 数据 axes 含 Z（层析/系列切片堆栈）时会按"帧序"处理并在日志提示；若切片间不是时间演化关系，请谨慎解读跨帧统计。
