# TIFF 堆叠查看与面积测量工具 v2

在 TIFF 单图或堆栈上手工绘制多边形，按标尺换算实际面积，并导出测量数据、顶点坐标、统计图和可恢复项目。

## Python 版本

- Python 3.8 / 3.9 / 3.10 / 3.11。
- 需要 tkinter（Python 标准库；Linux 请安装 `python3-tk`）。
- 依赖检查会验证 `tifffile`、`pandas`、`matplotlib`、`numpy`、`Pillow`、`openpyxl`。

## 直接运行

本仓库不含构建产物（无 `dist/` 目录），历史上分发的 `dist/TIFF面积测量工具v2.exe` 未随仓库分发。
需要 exe 请用项目内环境自行打包：

```powershell

.venv\Scripts\python -m PyInstaller 统计面积v2.spec
```


## 使用流程

1. 打开 TIFF 文件并浏览目标帧（或打开文件夹；多文件按**自然排序**合并，`Frame2` 排在 `Frame10` 之前）。存在未保存修改时会先要求确认，防止误点入口静默丢弃数据。
2. 通过已知长度的线段或手动输入设置"像素/实际单位"比例（标尺两点重合会被立即拦截）。
3. 逐点绘制多边形（绘制中有从最后顶点到光标的虚线预览），可命名、删除或复制到下一帧（复制链共享 lineage，用于追踪）；目标帧已有数据时复制需确认。
4. 检查像素面积/周长和换算后的 `nm²` 等实际面积。
5. 导出 CSV/XLSX、图表，或保存 JSON 项目供以后继续。
6. 大文件加载中可点击状态栏"取消加载"（多页 TIFF 每 25 页报一次进度）；关闭窗口时有未保存修改会先确认。

工具栏的"锁定对比度"复选框可以把显示的灰度范围固定为当前帧的 min/max：
默认 imshow 对每帧独立归一化，会掩盖帧间真实的强度变化，需要跨帧比较亮度时请打开锁定。

## 坐标约定（v3）

所有存储、显示与导出的坐标统一为**左上原点**：X 为列号，Y 为**自图像顶部起算的行号**，
与 ImageJ/Fiji 等图像工具一致。导出的 `*_coordinates.csv` 中 `Y坐标_像素` 即行号。

## 项目文件格式

- v3：`version: 3`，坐标为左上原点，新增 `image_height`/`image_width` 与 `polygon_roots`（多边形复制链 lineage）。
- v2 及更早：坐标以图像底部为 y=0 存储；**加载时自动迁移翻转**，并在帧数不一致或数据损坏时给出告警。
- 测量值在加载时从顶点重建（顶点是唯一数据源）；越界帧/畸形数据会被丢弃并在提示中注明数量。
  JSON 中的 `measurements` 字段仅供旧版本工具读取，本工具不使用它恢复数据。
- 加载时对标量字段做全面校验，非法值只降级为默认值并列入告警，不会进入换算/渲染路径：
  - 帧号钳制到 `[0, 总帧数-1]`（负值不再经 numpy 负索引回绕到帧尾）；
  - `pixel_to_unit_ratio` 须为正有限数，"已校准 + 非法比例"按未校准处理；
  - `unit_name` 须在白名单（nm/μm/um/mm/cm/m）内，白名单外回退 nm（该值会拼进导出表头）；
  - `ruler_points` 畸形整体忽略；颜色须能被 matplotlib 解析，否则改用默认色；
  - v3 记录的 `image_width/height` 与当前图像不一致时告警（坐标可能错位）；
    顶点落在图像范围外时计数提示（数据保留）。

## 数据维度支持

加载时先读取 `TiffFile` 元数据（`axes`、页数、形状）再做规范化：

| 输入形状 | 处理 |
| --- | --- |
| `(H, W)` 单张灰度 | `(1, H, W)` |
| `(H, W, 3/4)` 单张彩色（末轴通道） | 转 uint8 灰度后 `(1, H, W)` |
| `(C, H, W)` 单张平面彩色（`axes` 以 C/S 开头，如 `CYX`） | 转置后转灰度 `(1, H, W)`（不再误判为 C 帧灰度堆叠） |
| `(T, H, W)` 灰度堆叠 | 原样，**包括 `W=3/4` 的窄条堆叠**，不会误判为彩色 |
| `(T, H, W, 3/4)` 彩色堆叠 | 逐帧转 uint8 灰度后 stack |

彩色转灰度的位深处理：整型输入（如 uint16）按 dtype 最大值线性缩放到 0–255；
浮点输入全局 max ≤ 1.0 时视为 [0,1] 归一化，否则按 [0,255] 截断；NaN 计 0。
范围判断只看有限值——单个 ±Inf 不会把整张 [0,1] 图误判成 [0,255]。

单页 3D 灰度堆叠优先用 `tifffile.memmap`（**只读模式**，不会在 Windows 上锁住源文件）；
多页 TIFF 在后台线程中逐页读取（每 25 页报一次进度），主线程通过队列轮询更新 UI。
加载采用代次（generation）机制：并发发起新加载或点击取消时，旧任务的消息直接丢弃。

大文件防护：正式加载前用元数据估算内存占用，超过 2 GiB 先弹窗确认。

文件夹模式：单个文件损坏只跳过并在加载完成后列出，不拖垮整个文件夹；
混合位深显式统一 dtype（混入浮点时用 float32，避免 numpy 隐式提升成 float64 使内存翻倍）。

## 输出

- CSV 或 Excel：来源文件、导出时间、帧号、多边形 ID/名称、像素面积、像素周长和实际面积/周长。
- Excel 额外含"汇总"工作表；CSV 模式额外生成 `*_summary.csv`（各帧合计 + 全局统计：
  像素与实际单位均有均值/中位数/最小/最大，标准差为样本标准差 ddof=1）。
- `*_coordinates.csv`：所有多边形顶点坐标（Y 为左上原点行号）。
- `*_ruler.csv`：标尺信息（已校准时）。
- PNG/PDF：面积变化（按复制链 lineage 追踪）、每帧总面积、区域数量和面积分布图。
- JSON：图像路径与尺寸、标尺、多边形、颜色、名称与 lineage 等项目状态。
- 注入防护：名称列在 CSV 中以 `'` 前置转义（`=+-@` 开头）；Excel 中强制为文本单元格
  （openpyxl 默认把 `=` 开头的字符串按公式写入），单位白名单从源头拦截表头注入。

## 注意事项

- 多边形是逐帧保存的；复制到下一帧不会自动追踪边界变化，但共享 lineage 以便图表追踪。
- 实际面积的准确度完全取决于标尺校准和顶点选择。
- JSON 项目包含原图路径；移动原图后加载项目时会要求选择替代文件（取消则放弃本次项目加载）；
  项目指向 UNC 网络路径时会先确认（连接共享会向对方发送本机认证信息）。
- 顶点会自动 clamp 到图像范围 `[0,w]×[0,h]`；自相交或零面积（顶点共线）多边形
  在完成绘制时需明确确认才会保存（鞋带公式对蝴蝶形等给出的是区域之差）。
- 标尺校准状态使用布尔标志 `ruler_calibrated` 判断，导出/显示/保存均以该标志为准。
- 快捷键（←→切帧, Enter完成, Backspace撤销, Esc取消, Delete删除）挂在主窗口上，
  点击工具栏按钮后仍然可用；焦点在输入框/下拉框内时自动让位给控件默认行为。
- 渲染等内部错误会写入程序同目录的 `测量工具.log`（2 MB 轮转 × 3 个备份）
  并对用户节流弹窗提示。
